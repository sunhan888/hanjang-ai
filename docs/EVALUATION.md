# 정확도 평가

가장 중요한 지표는 **조용한 오답**입니다. 틀렸는데 '확인 필요'도 없이 화면에 나간 값을 말합니다.
핵심 3항목(의견진술기한·감경과태료·가상계좌)에서 0건이 목표입니다. 틀린 값을 '확인 필요'로 띄우는 것은 실패가 아니라 설계된 동작입니다.

## 1. 데이터

| 세트 | 위치 | 설명 |
| --- | --- | --- |
| 합성 20장 | `eval/testset/` | `eval/make_testset.py`로 만든다(seed 42, 기준일 2026-10-20 → 언제 돌려도 같은 20장). 양식 3종, 함정 8종, 화질 3단계. `conditions.csv`에 장별 함정과 실제 인쇄된 라벨이 있다 |
| 실물 견본 3장 | `eval/real/` (커밋 안 함) | 서울시·경찰서·진주시. 개인정보를 가린 사본 + 같은 열 구성의 `ground_truth.csv` |

함정 코드: `TS` 사진 속 시각, `YY` 두 자리 연도, `XY` 연도 경계, `RD` 감경액 병기, `50` 50% 감경 예시 금액, `DN` 헷갈리는 번호, `SD` 문장 속 기한, `MA` 계좌 여러 개.

## 2. 실행

```bash
python eval/run_batch.py --provider anthropic      # → eval/predictions.csv
python eval/evaluate.py --out eval/report.md
```

판독기(`--provider`)
- `mock-truth`: 정답을 그대로 돌려준다. 검증·채점 코드의 상한 확인용 (과업 성공 20/20이 나와야 정상)
- `mock-noisy`: 실물에서 본 실수를 함정별로 섞는다. 규칙이 무엇을 잡고 놓치는지 연습용
- `anthropic`, `openai`: 실제 모델 (20장 = 판독 호출 20번)

D-day 기준일은 `--today`로 고정합니다(기본 2026-10-20). 실제 날짜로 재면 매일 결과가 달라지기 때문입니다.

## 3. 채점 규칙

| 항목 | 정답 판정 |
| --- | --- |
| 과태료금액·감경과태료 | 숫자만 비교 |
| 의견진술기한·발행일·위반일시 | 정규화 문자열이 같아야 함 |
| 위반차량·문서종류 | 공백 무시 |
| 증거번호 | 공백·하이픈 무시 |
| 가상계좌 | 틀린 계좌가 하나도 없고, 맞는 계좌가 하나 이상 (하나만 읽어도 내는 데는 충분) |
| 발신기관 | 공백 무시, 뒷부분 일치 허용 (`마포구청장`도 정답) |
| 위반장소·위반내용 | 공백 무시 유사도 0.85 이상 |

## 4. 지표와 목표

| 지표 | 정의 | 목표 |
| --- | --- | --- |
| 조용한 오답 | 틀렸는데 '확인 필요'가 없는 칸 (핵심 3항목) | 0건 |
| 과업 성공 | 핵심 3항목이 모두 정답인 장 | 합성 18/20, 실물 3/3 |
| 오답 포착률 | 틀린 칸 중 '확인 필요'가 붙은 비율 | 높을수록 좋음 |
| 과잉 경고 | 맞았는데 '확인 필요'가 붙은 칸의 비율 | 10% 이하 |
| 처리 시간 | 한 장 판독 시간의 중앙값 | 20초 이하 |

목표는 설계서의 제안값입니다. 첫 실제 측정(10/22) 뒤 둘이 합의해 조정합니다.

## 5. mock-noisy 리포트 읽는 법

[sample_eval_report.md](sample_eval_report.md)는 mock-noisy로 돌린 결과입니다.

- 핵심 3항목 조용한 오답 0건, 과업 성공 12/20, 과잉 경고 0%.
- 과업 성공이 낮은 것은 정상입니다. 감경액 혼동(RD·50), 문장 속 기한(SD), 연도 오독(YY)을 규칙이 '확인 필요'로 잡았기 때문이고, 사용자는 종이를 확인하라는 안내를 받습니다.
- 남은 조용한 오답 7건은 사진 속 시각(TS) 4건과 옆 번호(DN) 3건입니다. 규칙이 아니라 프롬프트로 풀어야 할 과제입니다.
- mock-noisy에는 '우리가 예상한 실수'만 들어 있습니다. 실제 모델은 다른 실수를 할 수 있으니 기준은 실제 측정입니다.
